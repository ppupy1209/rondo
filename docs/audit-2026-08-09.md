## 1. `rondo test` 가 한국어에서 항상 실패 · 치명

### 증상

한국어 설정(`language=ko`, 기본값)에서 `rondo test` 의 모든 프로필이 실패한다. 사용자에게는
4KB 짜리 이스케이프된 KDL 원문이 그대로 출력된다.

```
rondo: Command '['zellij', 'action', 'new-tab', '--layout-string', 'layout {\n    tab
name="test-a9cb0667" ... args "--prompt-interactive" "[Rondo \\ub3c5\\ub9bd \\ud14c
\\uc2a4\\ud2b8 \\uc138\\uc158]\\n\\ubcc0\\uacbd\\ud560 ... ']' returned non-zero exit status 2.
```

영어 설정에서는 프롬프트가 ASCII 라서 동작한다. 즉 **한국어 기본 사용자는 독립 테스트 기능
전체를 쓸 수 없다.**

### 위치

`bin/rondo` `test_layout()` — 1445, 1446, 1449, 1455

```python
values.append(indent + "    args " + " ".join(json.dumps(arg) for arg in command[1:]))
```

`json.dumps` 는 기본 `ensure_ascii=True` 라서 비ASCII 를 `\uXXXX` 로 바꾼다. KDL 은 JSON 식
`\uXXXX` 이스케이프를 지원하지 않는다 (KDL 은 `\u{...}` 형식).

### 재현

Rondo 세션의 shell 탭에서:

```sh
rondo test review --from codex --tester gemini
```

최소 재현:

```python
import json, subprocess
layout = 'layout {\n tab name="zt" {\n  pane name="p" command="/bin/echo" {\n   args ' \
    + json.dumps("테스트") + '\n  }\n }\n}'
subprocess.run(["zellij", "action", "new-tab", "--layout-string", layout])
```

zellij 응답:

```
× Failed to parse Zellij configuration
 4 │             args "테스트"
   ·                    ▲
   ·                    ╰── Kdl Deserialization Error
```

### 제안

네 곳 모두 `ensure_ascii=False` 를 준다. 검증했다 — zellij rc `2` → `0`.

```python
json.dumps(arg, ensure_ascii=False)
```

`cwd={json.dumps(role['worktree'])}` 도 같이 고쳐야 한다. 사용자 이름이나 저장소 경로에
한글이 들어가면 같은 방식으로 깨진다.

`bin/rondo` `write_layout()` (788, 793) 은 ASCII 에이전트 이름만 쓰므로 영향 없다.

### 왜 테스트가 못 잡았나

`tests/test_rondo.py:270` `test_test_layout_has_only_fresh_verifier_panes` 는 생성된
문자열에 `name="test-` 가 있는지만 본다. KDL 로 파싱하지 않고, 한국어 프롬프트로 돌리지도
않는다. 회귀 테스트는 **비ASCII 프롬프트를 넣고 KDL 파서를 통과하는지** 를 봐야 한다.

## 2. `rondo send` 가 신뢰 프롬프트를 대신 승인하고 메시지를 잃음 · 치명

> **보안 이슈다.** `rondo send` 는 대상 패널의 상태를 확인하지 않고 붙여넣기 + Enter 를 보낸다.
> 갓 시작한 에이전트 CLI 는 "이 폴더를 신뢰합니까?" 프롬프트에 멈춰 있고, 그 상태에서 Enter 는
> 기본 선택지인 "Yes, I trust this folder" 를 확정한다. 사용자 대신 보안 결정을 내리는 것이다.

### 증상

실측 순서:

1. 데모 저장소에서 `rondo` 실행. claude 패널이 이 화면에서 대기:

```
 Quick safety check: Is this a project you created or one you trust?
 ❯ 1. Yes, I trust this folder
   2. No, exit
 Enter to confirm · Esc to cancel
```

2. 외부 셸에서 실행:

```sh
rondo send claude "hello from rondo send test"
```

3. 출력: `claude 패널에 메시지를 보냈습니다.`

4. 패널 실제 상태 — 신뢰 프롬프트는 **통과됐고**, 보낸 메시지는 **사라졌다**:

```
╭─ Claude Code ──────────────────────╮
│      Welcome back KimYeonWoo!      │
╰────────────────────────────────────╯
❯
```

gemini 패널도 동일한 신뢰 프롬프트에 있었는데 `rondo audience guided` 브로드캐스트가
같은 방식으로 통과시켰다.

결함은 두 개다.

- **준비 상태 확인 없음** — 대상 TUI 가 입력을 받을 수 있는 상태인지 보지 않는다.
- **전달 검증 없음** — 보낸 적 없는 메시지도 "보냈습니다" 로 보고한다.

### 위치

`bin/rondo` `send_agent_message()` — 903

```python
pane = find_agent_pane(name, session_name)
subprocess.run(command + ["action", "paste", "--pane-id", pane, "--", message], check=True)
subprocess.run(command + ["action", "send-keys", "--pane-id", pane, "Enter"], check=True)
print(t("sent", name=name))
```

같은 무방비 경로를 공유하는 기능:

| 기능 | 경로 |
|---|---|
| `rondo send` | 직접 호출 |
| `rondo audience <단계>` | 열린 패널 전체 브로드캐스트 |
| `rondo continue` | 대기 중인 인계 전달 |
| `relay auto` | **사용자 없이 자동 실행** |
| `rondo resume` | `open_session(resume_agent=...)` |
| `rondo lens` | 요소 맥락 전달 |

`relay auto` 가 가장 위험하다. 사용량 한도에 닿으면 사용자가 자리에 없어도 실행되므로,
무인 상태에서 신뢰 게이트를 통과시킬 수 있다.

### 이미 알고 있던 문제

`bin/rondo` `race_send()` — 1752 에는 대기 로직이 있다.

```python
deadline = time.monotonic() + wait          # 기본 4.0초
while len(panes) < len(race.agents) and time.monotonic() < deadline:
    time.sleep(0.3)
    panes = race_panes()
time.sleep(1.0)  # TUI 가 입력을 받을 준비를 할 틈
```

주석까지 달려 있는데 `race` 에만 있고 주 경로에는 없다.

### 제안

1. 전송 전 `zellij action dump-screen --pane-id <id>` 로 화면을 읽고, 신뢰/선택/확인
   프롬프트 패턴이 보이면 **거부**한다. 에이전트별 패턴은 어댑터 계층에 둔다.
2. 전송 후 화면을 다시 읽어 메시지가 실제로 반영됐는지 확인한 뒤에만 성공 문구를 출력한다.
3. `race_send` 의 대기·정착 로직을 `send_agent_message` 로 올리고 `race_send` 는 그걸 쓴다.
4. `relay auto` 는 대상 패널이 프롬프트 대기 상태면 자동 전달을 중단하고 `ready` 로 낮춘다.

## 3. 오타 한 번이 좀비 세션을 만든다 · 치명

### 증상

`rondo` 의 미지의 첫 인자는 전부 **새 세션 이름**으로 처리된다. `rondo prooof` 같은 오타가
`rondo-prooof-<hash>` 세션을 만들고, 에이전트 패널까지 기동하고, 영구히 남는다.

감사 중에 오타와 잘못된 인자만으로 9개가 쌓였다:

```
rondo-prooof-7b5a62370b
rondo-git-bogus-7b5a62370b
rondo-relay-bogus-7b5a62370b
rondo-audience-bogus-7b5a62370b
rondo-test-bogus---from-codex---tester-claude-7b5a62370b
rondo-code-review-bogus-7b5a62370b
rondo-resume-bogus-7b5a62370b
rondo-test-all-7b5a62370b
rondo-test-status-7b5a62370b
```

각각 zellij server 프로세스를 물고 있고, 그 안에서 agent CLI 가 돌아간다.

```
/opt/homebrew/bin/zellij --server /tmp/rondo-501/contract_version_1/rondo-prooof-7b5a62370b
/opt/homebrew/bin/zellij --server /tmp/rondo-501/contract_version_1/rondo-git-bogus-7b5a62370b
...
```

터미널에서는 zellij 의 Rust 패닉이 그대로 보인다:

```
thread 'main' panicked at zellij-client/src/os_input_output.rs:166:48:
could not enable raw mode: Os { code: 6, kind: Uncategorized, message: "Device not configured" }
```

Rondo 에는 세션 삭제 명령이 없어서 `zellij delete-session --force` 로 직접 치워야 한다.

### 위치

`bin/rondo` `main()` — 2021

```python
elif command:
    open_session(command)
else:
    open_session()
```

`open_session(custom_name)` 은 813 에서 `rondo_session_name(root, custom_name)` 으로
넘어간다. 이 커스텀 이름 기능 자체가 `rondo --help` 에 없다.

### 제안

- 알려진 명령 화이트리스트를 만들고, 미매치는 `rondo: 알 수 없는 명령: prooof` + exit 1.
  가까운 명령 제안(`혹시 proof?`)까지 있으면 더 좋다.
- 커스텀 세션 이름이 필요하면 `rondo attach <name>` 처럼 명시 명령으로 분리하고 help 에 적는다.
- `rondo kill [세션]` / `rondo clean` 을 추가해 Rondo 안에서 세션을 정리할 수 있게 한다.
- `rondo -l` 은 현재 `zellij list-sessions` 를 그대로 exec 해서 Rondo 와 무관한 세션까지
  보여준다. `rondo-` 접두사로 거르고 현재 저장소 세션을 표시하면 좋다.

## 4. `rondo undo <id>` 가 인자를 무시한다 · 높음

### 증상

`rondo undo --list` 는 스냅샷 **ID** 를 보여준다.

```
스냅샷 (최신 먼저)
  b0a8ea9e  08-09 20:13  rondo undo 직전
  3772b8ed  08-09 20:10  rondo snapshot
  9a90f859  08-09 20:05  before-experiment
```

그 ID 를 그대로 넣으면 조용히 무시되고 1단계만 되돌린다. 그러고는 **요청하지 않은 다른 ID** 로
성공 메시지를 낸다.

```sh
$ rondo undo 9a90f859
8fe8ccf2 시점으로 작업 트리를 되돌렸습니다. 직전 상태는 c288acd7 에 있습니다 (rondo undo 로 복귀).
```

대상이 작업 트리라서 조용한 오작동의 대가가 크다.

### 위치

`bin/rondo` `undo_command()` — 1949

```python
steps = 1
for value in args:
    if value.isdigit():
        steps = int(value)
```

인자는 **단계 수**만 받는다. `9a90f859` 는 `isdigit()` 이 아니므로 버려진다.

### 곁가지

- 확인 프롬프트가 없다. 파괴적 동작이 즉시 실행된다.
- 추적하지 않는 파일이 사라진다. 감사 중 `.rondo/handoff.md` 가 삭제됐다. 직전 상태 스냅샷을
  자동으로 만들어 주므로 회수는 가능했다.
- `rondo undo N` (단계 수) 기능이 help 에 없다. help 는 `rondo undo [--list]` 만 적는다.
- 매 undo 가 "rondo undo 직전" 스냅샷을 새로 쌓기 때문에, 반복 실행하면 과거로 계속 가는 게
  아니라 두 상태를 오간다.

### 제안

- 짧은 해시를 받아 해당 스냅샷으로 복원한다. 모르는 값이면 무시하지 말고 에러를 낸다.
- 단계 수는 `--steps N` 으로 분리하고 help 에 적는다.
- 복원 전에 무엇이 사라지는지(추적 안 되는 파일 포함) 요약하고 확인을 받는다. `--yes` 로 생략.
- 반복 undo 가 과거로 이동하도록 커서를 두거나, 최소한 현재 동작을 help 에 설명한다.

## 5. `--scope` 가 위험 이유를 뭉갠다 · 높음

### 증상

`rondo task ... --scope web` 을 준 Python 저장소에서, 서로 성격이 완전히 다른 파일이 전부
동일한 이유로 분류된다.

```
| Risk | File | Reason |
|---|---|---|
| high | `migrations/001_add_col.sql`  | scope_drift |
| high | `src/auth.py`                 | scope_drift |
| high | `src/config.py`               | scope_drift |
| high | `src/__pycache__/auth...pyc`  | scope_drift |
```

`src/config.py` 에는 `SECRET_KEY = '...'` 가 들어 있고, `migrations/` 는 README 가 명시한
고위험 경로지만, 사람이 받는 정보는 "scope 밖" 하나뿐이다. **왜 위험한지** 를 알 수 없다.

### 위치

`lib/rondo/proof.py` `risk_for()` — 87

```python
if not scoped:
    return {"path": path, "level": "high", "reason": "scope_drift", "seconds": 90}
if parts & HIGH_MARKERS or tokens & HIGH_MARKERS:
    return {"path": path, "level": "high", "reason": "sensitive_path", "seconds": 90}
```

scope 불일치에서 즉시 반환하므로 `HIGH_MARKERS` (auth, migration, secret, payment, …) 평가에
도달하지 못한다.

### 제안

`scope_drift` 를 이유의 **대체**가 아니라 **추가 태그**로 만든다.

```python
reasons = []
if not scoped:
    reasons.append("scope_drift")
if parts & HIGH_MARKERS or tokens & HIGH_MARKERS:
    reasons.append("sensitive_path")
```

`migrations/001_add_col.sql · scope_drift + sensitive_path(migration)` 처럼 나와야 사람이
어디부터 볼지 정할 수 있다.

## 6. Proof 가 자기가 만든 파일을 위험으로 센다 · 높음

### 증상

`rondo proof` 는 검증 명령을 실행한 **뒤**에 변경 파일을 센다. unittest 가 만든
`__pycache__/*.pyc` 가 변경 목록에 들어오고, 고위험 사람 검토 항목이 된다.

```
## Human review queue
- **high** · migrations/001_add_col.sql · ~90s
- **high** · src/__pycache__/auth.cpython-313.pyc · ~90s
- **high** · src/auth.py · ~90s
- **high** · src/config.py · ~90s
- **high** · tests/__pycache__/test_auth.cpython-313.pyc · ~90s
```

5개 중 2개가 Proof 자신이 만든 바이너리다. `.gitignore` 가 없는 저장소에서 재현된다
(`changed_files()` 는 `--exclude-standard` 를 쓰므로 `.gitignore` 가 있으면 가려진다).

### 위치

`lib/rondo/proof.py` `changed_files()` — 71

### 제안

- 검사 실행 **전에** 변경 목록을 스냅샷으로 고정하고, 그 목록으로만 위험도를 계산한다.
- 그와 별개로 흔한 빌드 산출물(`__pycache__/`, `*.pyc`, `node_modules/`, `dist/`, `build/`,
  `.venv/`, `target/`)은 `.gitignore` 유무와 무관하게 기본 제외한다.
- `rondo handoff` 의 작업 트리 목록에도 같은 노이즈가 들어간다.

## 7. 변경 0개인데 "승인 후보" · 높음

### 증상

아무것도 바꾸지 않은 저장소에서:

```
$ rondo proof
Rondo Proof · 승인 후보
  검증 1개 통과 · 0개 미해결
  변경 0개 · 고위험 0 · 중간 0 · 낮음 0
  사람 판단 항목 0개
```

"승인 후보" 는 초록불로 읽힌다. 실제로는 검증할 대상이 없었을 뿐이다. 작업했다고 착각한
사용자가 그대로 넘어갈 수 있다.

### 제안

변경 0개면 별도 상태로 처리한다.

```
Rondo Proof · 변경 없음
  검증할 대상이 없습니다. 작업 후 다시 실행하세요.
```

### 곁가지

`rondo proof --no-checks` 는 "변경 5개" 인데 "사람 판단 항목 6개" 를 낸다. 6번째가 무엇인지
출력에 설명이 없다.

## 8. 에이전트 하나가 없으면 작업공간 전체가 막힌다 · 높음

### 증상

`panels=claude codex kimi` 인데 kimi 가 설치돼 있지 않으면:

```sh
$ rondo
rondo: kimi이(가) 설치되지 않았습니다. `rondo doctor`로 확인하세요.
```

세션이 아예 열리지 않는다. 선택 CLI 하나 때문에 claude·codex 도 못 쓴다. 안내받은
`rondo doctor` 를 실행해도 "kimi 필요" 를 반복할 뿐 해결 경로가 없다.

### 위치

`bin/rondo` `open_session()` — 832

```python
unavailable = [name for name in panels if not installed(name)]
if unavailable:
    raise RuntimeError(t("not_installed", name=", ".join(unavailable)))
```

### 제안

- 없는 에이전트는 건너뛰고 경고만 낸 뒤 나머지로 세션을 연다.
- 전부 없을 때만 실패시키고, 그때는 `rondo setup` 을 안내한다.
- 한국어 조사 처리: `kimi이(가)` 는 폴백 형태다. 받침 유무로 `이/가` 를 고르면 자연스럽다.

## 9. `rondo code-review all` 이 4패널 원칙을 위반한다 · 높음

### 위치

`bin/rondo` `code_review_command()` — 1382

```python
reviewers = [name for name in reviewers if installed(name)][:MAX_PANELS]
...
for name in reviewers:
    subprocess.run(["zellij", "action", "new-pane", "--name", f"review-{name}", ...])
```

`reviewers` 는 4개로 자르지만 **이미 열려 있는 패널 수를 세지 않는다.** 에이전트 3개가 떠

`rondo add` (858) 는 이미 이 검사를 한다 — 같은 규칙을 쓰면 된다.

## 10. `rondo pr` 이 틀린 에러를 낸다 · 높음

### 증상

Git 저장소가 맞는데 origin 이 없을 때:

```sh
$ rondo pr "테스트 PR"
rondo: 현재 폴더는 Git 저장소가 아닙니다. `rondo git connect <URL>`로 연결하세요.
```

`git rev-parse --is-inside-work-tree` 는 `true` 다. 사용자는 엉뚱한 곳을 의심하게 된다.

### 위치

`bin/rondo` `pr_command()` — 1614

```python
require_git_repo(root)
if not git_origin(root):
    raise RuntimeError(t("git_not_repo"))
```

### 제안

전용 문구를 만든다. 예: `origin 원격이 없습니다. `rondo git connect <URL>` 로 연결하세요.`

### 곁가지

`rondo git` 도 origin 이 `-` 일 때 다음 행동을 알려주지 않는다.

```
Git 연결
  origin: -
```

## 11–18. 중간

### 11. 검토 예산이 지켜지지 않는다

```sh
$ rondo review --budget 30s
검토 예산 30초 · 우선 확인
  1. ! migrations/001_add_col.sql  ~90s
```

`lib/rondo/proof.py` `review_queue()` — 247

```python
if not selected or spent + item["seconds"] <= budget:
```

첫 항목은 무조건 넣는다. 의도는 이해되지만 예산을 넘겼다는 사실을 말하지 않는다.
`예산 30초 · 최소 1개 표시 (~90초 소요)` 처럼 알려야 한다.

### 12. 검토 큐 정보가 부족하다

항목이 파일명과 `~90s` 뿐이다. 위험 이유, 변경 줄 수, 무엇을 봐야 하는지가 없다. 시간 추정도
내용과 무관한 고정값이라 1줄 변경과 500줄 변경이 똑같이 90초다.

### 13. 상태 표시줄이 잘린다

`bin/ai-status` — 167

```python
width = shutil.get_terminal_size(fallback=(80, 24)).columns
if len(text) > width:
    text = text[: max(0, width - 1)]
```

단어 중간에서 하드 절단된다. 실제 출력:

```
claude Opus 5 high 5h ▓▓▓▓▓▓▓░ 93%(4h47m) wk ▓▓▓▓░░░░ 53%(20h47m) 2m전   codex g
```

gemini 정보가 통째로 사라진다. 상태 표시줄은 이 제품의 대표 기능인데 3패널 기본 구성에서
이미 넘친다. 폭에 따라 모델명 → 창 이름 → 절대 시간 순으로 줄이고 퍼센트를 마지막까지
남기는 우선순위 축약이 필요하다.

### 14. `rondo audience` 가 사용량을 쓴다

표시 수준을 바꾸는 것뿐인데 열린 패널 전부에 프롬프트를 보내고 각 에이전트가 응답을 생성한다.
실측에서 Claude 사용량에 반영됐다. 조용히 적용할 수 있으면 그렇게 하고, 불가능하면 실행 전에
"패널 3개에 전달합니다 (사용량 소모)" 를 알린다.

### 15. `rondo doctor` 가 선택 CLI 를 "필요" 로 표시한다

```
– kimi       필요
```

kimi 는 필수가 아니다. 영어판은 `missing` 으로 정확하다. 한국어도 `미설치` 또는 `선택` 이
맞다.

### 16. Git 저장소가 아닌 곳에서 조용히 동작한다

`bin/rondo` `repo_root()` — 678 은 git 실패 시 `Path.cwd()` 로 폴백한다. `~/Downloads` 에서
`rondo` 를 실행하면 그 디렉터리에 작업공간이 만들어지고 에이전트가 기동한다. 감사 중
`rondo-notgit-10743c4a4a` 세션이 실제로 생성됐다. `workspace` 승인 모드와 겹치면 위험하다.

세션을 여는 명령은 Git 저장소를 요구하거나, 최소한 확인을 받아야 한다.

### 17. 캐시가 영구히 쌓인다

저장소를 지워도 `~/.cache/rondo/claude.<hash>.json`, `~/.cache/rondo/test/<hash>/worktrees/`
빈 디렉터리가 남는다. 정리 명령이 없다. `rondo clean` (또는 `rondo doctor --clean`) 으로
없어진 저장소의 캐시를 지울 수 있으면 좋다.

### 18. 세션 감지 환경변수가 명령마다 다르다

| 함수 | 확인하는 값 |
|---|---|
| `add_agent` (853) | `ZELLIJ` |
| `send_agent_message` (908) | `ZELLIJ_SESSION_NAME` |
| `code_review_command` (1366) | `ZELLIJ_SESSION_NAME` |

같은 질문("Rondo 세션 안인가")에 다른 키를 쓴다. `send` 는 `session_name` 인자로 외부에서도
대상을 지정할 수 있는데 `add` 는 못 한다. 헬퍼 하나로 통일하는 게 좋다.

## 확인된 정상 동작

감사 중 기대대로 동작한 것:

- `rondo doctor --deep` — 벤더 데이터 신선도(`limits · 8661초 전`)까지 정확히 보고
- `rondo handoff` — 출력 파일이 깔끔하고 자격증명·대화 원문 없음

- `rondo lens` 원격 차단 — `--allow-remote` 없으면 정확히 거부
- `rondo audience` 브로드캐스트 — 3패널 전부 새 기준을 실제로 반영
- `rondo undo` 왕복 — 직전 상태 스냅샷 덕에 데이터 회수 가능
- 세션 이름 해시 — origin + 실제 경로 조합이라 같은 이름 저장소끼리 충돌하지 않음
- `rondo task` / `rondo git` / `rondo relay` 인자 검증과 exit code
